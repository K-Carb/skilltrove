## What it does

这是一个"先调研再动手"的流程技能。以功能需求描述和现有代码为输入，围绕一个待实现功能执行一轮方案调研，最终交付一份结构化调研报告：候选方案、对比维度、推荐结论与理由。

## When to use

- 要给某个功能做技术选型
- 多种实现方案之间拿不定主意
- 需要向团队说明"为什么选这个方案"

## Steps

1. **明确候选方案**：列出 2-4 个主流实现路线，不遗漏"最土但够用"的那个。
2. **定对比维度**：成本、迁移难度、长期维护、与现有系统的契合度，按功能实际关切取舍。
3. **逐项对比**：每个候选按同一组维度评估，结论落来源（文档、源码、实测）。
4. **给出推荐**：一个明确结论加理由，不写"都可以"。

## Deliverable

一份 Markdown 调研报告：候选清单、对比表、推荐结论与理由、证据缺口声明（哪些结论证据不足）。
